# Харнесс SysCall для openJiuwen Challenge 2026 — дизайн

Источники: `context/Task/Регламент соревнования.md`, `context/faq.txt`, ответы организаторов в чате (07.11), решения владельца в сессии 2026-11-07.

## Зачем

За один прогон (1 час, бюджет ~100K выходных токенов, 10 входных = 1 выходной, рассуждения считаются как выходные) набрать максимум баллов на 100 задачах четырёх типов: `math`, `data_analysis`, `search`, `coding`. При равенстве баллов побеждает тот, кто потратил меньше токенов.

## Цели

- Решать кодом всё, что решается кодом: 0 токенов (владелец: «если задача решается кодом — решать кодом, жюри это засчитывает»).
- Модель — только там, где детерминированный решатель не справился; порядок по reward / оценка токенов.
- Ни одна решённая задача не теряется: `answer.txt` пишется сразу, с `fsync`.
- Прогон никогда не падает: исчерпание бюджета, ошибки прокси и таймауты завершают работу штатно, с кодом 0.

## Не цели

- Отдельный классификатор невыполнимых задач (CatBoost и т. п.): штрафа за неверный ответ нет, а парсер сам видит отсутствие данных.
- Картинки вместо текста: замер дал экономию ~2,3× только на больших таблицах, ценой ошибок; таблицы и так считаются кодом.
- Любые обходы учёта токенов на прокси, сеть кроме прокси, вмешательство в проверку — дисквалификация на security-проверке.

## Ограничения (из регламента и чата)

- Запуск: `python /app/run_agent.py --tasks-dir /data/tasks`, env `LLM_BASE_URL`, `LLM_API_KEY`, `BUDGET` (например `100000`). `OUT` не используется (организатор, 07.11).
- Контейнер: `--read-only`, запись только в `/data/tasks` и `/tmp` (2 ГБ), `HOME=/tmp`, 8 CPU (организатор, 07.11), 16 ГБ RAM, `--pids-limit 512`, `timeout 1h`, без сети кроме прокси.
- До 5 одновременных сессий агента (запросов к модели).
- Модели: `qwen3.8-27b`, `qwen3.8-27b-noreason`, `qwen3.6-35b-a3b`, `qwen3.6-35b-a3b-noreason`.
- Харнесс на базе openJiuwen (обязательно, FAQ); `openjiuwen==0.1.19` из PyPI.
- Образ < 4 ГБ, сборка < 1000 с, репозиторий < 100 МБ, версии зависимостей и тег базового образа зафиксированы, ключей в репозитории нет, при запуске ничего не скачивается.
- Ответ: `answer.txt` в каталоге задачи рядом с `task.json`. Невыполнимая задача — файл не создаётся; штрафа за неверный ответ нет (владелец).
- В финальном наборе нет поля `expected`; `task_type`, `instruction`, `reward`, `check` остаются (FAQ).

## Как устроено

1. Загрузка всех задач, поле `reward` и `check` видны сразу.
2. Фаза 1 — детерминированные решатели параллельно на 8 процессах:
   - `math`: разбор шаблонных предложений про склад в последовательность операций;
   - `data_analysis`: разбор вопроса (метрика, фильтры product/region/month) и вычисление по CSV;
   - `search`: граф из `kb/*.md` (`Ключ: значение`), разбор цепочки вопроса (человек → работодатель → штаб-квартира и т. п.);
   - `coding`: перебор однотокенных обратных мутаций в функциях, чьи тесты падают, с прогоном тестов в подпроцессе.
   Результат: `solved` (ответ записан — пишется всегда, когда решатель получил хоть какой-то ответ, например `0` для пустой выборки: штрафа нет), `infeasible` (ответа нет вовсе — человек не найден, деление на 0; пропуск без токенов), `unparsed` (передаётся в фазу 2).
3. Фаза 2 — модель через openJiuwen для `unparsed`, по убыванию reward / оценка токенов, до 5 параллельно:
   - `math` / `data_analysis` / `search`: модель без рассуждений пишет короткую Python-программу, харнесс её исполняет в каталоге задачи и пишет stdout в `answer.txt`;
   - `coding`: модель получает `mylib.py`, тесты и вывод упавших тестов, возвращает только исправленные функции; тесты прогоняются локально; повтор на `qwen3.8-27b-noreason`, затем (для reward ≥ 3) на `qwen3.8-27b` с `reasoning_effort: low`.
4. Учёт бюджета по `usage` каждого ответа: `prompt_tokens/10 + completion_tokens`; задача не стартует, если её оценка больше остатка за вычетом резерва.

Решение, тратить ли токены на нераспознанные формулировки, владелец оставил разработчику: по умолчанию тратим, если ROI задачи выше порога, порог подбирается на тренировочном наборе.

## Что оставлено исполнителю

Тексты промптов, конкретный набор мутаций, шаблоны генератора тренировочных задач, значения резерва и порогов (подбираются на тренировочном прогоне).
