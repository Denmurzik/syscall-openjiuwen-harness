# SysCall Harness Round 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** поднять баллы на скрытом финальном наборе и срезать токены по разведке `.superpowers/sdd/round2/tricks-report.md` (локальный файл, пункты 1–8, 10, 11).

**Architecture:** без изменения двухфазной схемы. Фаза 1 пишет «предварительные» ответы и отдаёт кандидатов; фаза 2 получает новый юнит арбитража coding и финальный проход лучших догадок; JSON-маршрут math переходит на шаги-выражения над `x`; search и data_analysis закрывают типовые перефразы без модели.

**Tech Stack:** как в `docs/superpowers/plans/2026-11-07-harness.md`.

**Spec:** `docs/superpowers/specs/2026-11-07-harness-design.md` + решения владельца 2026-11-08: баллы важнее токенов, токены — только тай-брейк; любую догадку записывать (штрафа нет); тратить токены только там, где вызов может изменить ответ.

## Global Constraints

- Все ограничения `docs/superpowers/plans/2026-11-07-harness.md` (Global Constraints) в силе, кроме `LLM_CONCURRENCY`: по умолчанию 3, env `HARNESS_LLM_CONCURRENCY`.
- `SolveResult` расширяется обратно совместимо: новые поля `tentative: bool = False`, `extra: dict | None = None`. Старые вызовы `SolveResult(status, answer, note)` работают как прежде.
- «Предварительный» ответ (`status="solved", tentative=True`) записывается в `answer.txt` сразу, но задача остаётся доступной фазе 2; окончательный ответ фазы 2 его перезаписывает.
- Структурированный вывод (`response_format`, `extra_body.guided_regex`) используется только с откатом: если прокси отвечает 400, повторить без него один раз и запомнить отказ в `LLMClient`.
- Арбитраж и любые новые вызовы модели: `temperature=0`, `max_tokens` ≤ 8 для выбора варианта.
- Коммиты без трейлеров.

## Review Focus

1. Предварительный ответ coding переписывается арбитражем только после полного зелёного прогона видимых тестов на выбранном варианте; тесты никогда не меняются.
2. Безопасный вычислитель выражений math не исполняет ничего, кроме `x`, целых констант, `+ - * //`, унарного минуса и скобок; деление на 0 → infeasible; огромные числа (>10^18) → unparsed.
3. Свободный парсер search срабатывает только при ровно одном имени из kb в вопросе и только на закрытом словаре; иначе unparsed.
4. Падение любого нового пути не роняет прогон и не отнимает уже записанный ответ.
5. Если прокси не поддерживает structured output, арбитраж и 2a всё равно работают (откат).

### Task 13: Coding — кандидаты, арбитраж и предварительные ответы

**Files:**
- Modify: `harness/result.py`, `harness/solvers/coding_solver.py`, `harness/scheduler.py`, `harness/llm_routes.py`
- Create: `harness/solvers/probe.py`, `harness/arbitrate.py`
- Test: `tests/test_probe.py`, `tests/test_arbitrate.py`, дополнения в `tests/test_coding_solver.py`, `tests/test_scheduler.py`, `tests/test_llm_routes.py`

**Interfaces:**
- Produces:
  - `SolveResult.tentative: bool = False`, `SolveResult.extra: dict | None = None`
  - `harness.solvers.probe.behaviour(mylib_src: str, func: str, inputs: list[tuple], timeout: float = 5) -> list[str]` — repr результата (или `"<exc:Type>"`) для каждого входа, в одном подпроцессе через `harness.proc.run_python`
  - `harness.solvers.probe.inputs_from_call(args: tuple, n: int = 6, seed: int = 0) -> list[tuple]` — пробные входы той же формы (списки int, строки, числа)
  - coding `solve` при неоднозначности: `SolveResult("solved", "DONE", note, tentative=True, extra={"ambiguous": [{"func": str, "candidates": [str, ...], "chosen": int}], "visible_asserts": [str, ...]})` — `candidates` = исходники функции по одному представителю каждого поведенческого кластера, `chosen` = индекс уже записанного варианта
  - coding `solve` при частичном ремонте (не все тесты зелёные): пишет лучший частичный `mylib.py`, возвращает `SolveResult("solved", "DONE", note, tentative=True)`
  - `async harness.arbitrate.arbitrate(task: Task, extra: dict, client) -> SolveResult` — один вызов на задачу, все неоднозначные функции в одном промпте, ответ — номера вариантов (`guided_regex` с откатом, `max_tokens` ≤ 8); если выбор отличается, собрать `mylib.py`, полный зелёный прогон видимых тестов, затем `write_mylib`; иначе ничего не менять
- Scheduler: фаза 2 получает юнит `2c` (арбитраж) для задач с `extra.ambiguous` — выполняется до 2b; предварительные ответы coding без `ambiguous` идут в 2b как сейчас (если 2b решил — перезапись); в конце `run` финальный проход: для задач без `answer.txt`, у которых есть сохранённая догадка (`SolveResult.extra["best_guess"]` или tentative-ответ), записать её.
- `llm_routes.fix_coding`: шаг с рассуждениями разрешён для любой награды, если `ledger.remaining() > 0.5 * budget` (через `client.ledger`); иначе прежний порог `reward >= 3`.

- [ ] Тесты (сначала падают): кластеризация двух мутантов с разным поведением → два кандидата; однозначный случай → без `ambiguous`; арбитраж с фейк-клиентом выбирает 2-й вариант → `mylib.py` переписан и тесты зелёные; фейк выбирает исходный → файл не тронут; фейк возвращает мусор/400 → откат без structured output, затем без изменений; частичный ремонт → tentative + `answer.txt` "DONE"; планировщик: tentative-задача попадает в 2b/2c, окончательный ответ перезаписывает; финальный проход пишет догадку; порог рассуждений по остатку бюджета.
- [ ] Реализация; измерить на генераторе (`tools/gen_tasks.py`, все пары «функция × видимый кейс», как в `.superpowers/sdd/round2/tricks-report.md` п. 1): доля неоднозначных, после арбитража с живой моделью (≤ 40 вызовов dev API) — доля верных на скрытых тестах.
- [ ] Полный набор через test-lock, коммит `feat: coding candidate arbitration and tentative answers`.

### Task 14: Search и data_analysis без токенов

**Files:**
- Modify: `harness/solvers/search_solver.py`, `harness/solvers/data_solver.py`
- Test: `tests/test_search_solver.py`, `tests/test_data_solver.py`

**Interfaces:**
- `search_solver.execute`: если конечное поле встречается в kb только у компаний (Headquarters, Founded), а текущая сущность — человек с полем Employer, добавить шаг Employer.
- `search_solver.parse_loose(instruction: str, kb: dict) -> dict | SolveResult` — запасной разбор после строгого `parse`: ровно одно имя из kb в вопросе; k = число слов «mentor»; поле по словарю (born/birth → Born; founded/established → Founded; city/headquarter/based/located/work → Headquarters; «who … mentor» → Mentor; «which company/employer/work for» → Employer); любое неизвестное значимое слово → `unparsed`.
- `data_solver`: метрика `top_product_units` (и общий вид `top_<column>_<sum_units|sum_revenue|count_orders>` для product/region) — «Which product sold the most units…», «Which region had the highest revenue…»; ничья → `unparsed`; ответ — значение колонки как в CSV.
- `data_solver.parse_loose(instruction, workspace) -> dict | SolveResult` — запасной разбор по словарю: значения product/region, реально присутствующие в CSV; месяцы — числа после «month(s)»; метрика по ключевым словам; неоднозначность → `unparsed`.

- [ ] Тесты на каждую формулировку из «novel»-вариантов `tools/gen_tasks.py` и на закрытые отказы (два имени, неизвестное слово, ничья в top).
- [ ] Реализация, полный набор через test-lock, коммит `feat: zero-token search coercion, loose parsers, top metrics`.

### Task 15: Модель, шаги-выражения math, компактный JSON

**Files:**
- Modify: `harness/config.py`, `harness/json_route.py`, `harness/solvers/math_solver.py`, `harness/llm_routes.py`
- Test: `tests/test_json_route.py`, `tests/test_math_solver.py`, `tests/test_llm_routes.py`

**Interfaces:**
- `harness.config.MODEL_FAST: str`, `MODEL_ALT: str`, `MODEL_REASON: str` — единое место для имён моделей; `json_route`/`llm_routes`/`arbitrate` берут их отсюда.
- `math_solver.execute_steps(spec: dict) -> SolveResult` — спецификация `{"start": int, "steps": [str, ...]}`, шаг — выражение над `x` (безопасный AST-вычислитель: `x`, int, `+ - * //`, унарный минус, скобки; `//0` → infeasible; |x| > 10**18 → unparsed).
- `json_route`: схема math — `{"start": "{N1}", "steps": ["x-{N2}*{N3}", "x-x//4", ...]}` с однострочным примером; плейсхолдеры внутри выражений подставляются `fill`; старый формат `ops` принимается как прежде. Схема data_analysis дополняется метриками `top_*` из задачи 14. Правило «JSON в одну строку без пробелов».
- Выбор `MODEL_FAST` — по замеру: генератор `--novel 1.0`, по 15 нераспознанных задач math/data/search, обе модели (`qwen3.6-35b-a3b-noreason`, `qwen3.8-27b-noreason`) через 2a и 2b, сравнить точность и токены (≤ 60 живых вызовов); победитель — `MODEL_FAST`, второй — `MODEL_ALT` (используется вторым шагом `fix_coding`). Решение и цифры — в отчёт и README.

- [ ] Тесты: вычислитель (разрешённые/запрещённые узлы, деление на 0, переполнение); 2a math со steps с фейк-клиентом; плейсхолдер внутри выражения; data `top_*` через 2a.
- [ ] Реализация, замер, полный набор через test-lock, коммит `feat: math expression steps, model choice by measurement`.
